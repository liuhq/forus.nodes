# 内容制作与本地化流程

## 文件约定

唯一故事使用：

```text
docs/scripts/h5-incident/package.yaml
docs/scripts/h5-incident/day-01-zh-CN.yaml
docs/scripts/h5-incident/day-01-en-US.yaml
...
docs/scripts/h5-incident/day-07-en-US.yaml
```

`package.yaml` 不含本地化文本，声明 `duration_days`、日期顺序、路线关键线索和结局优先级。故事、日期、账号、线索、卡牌、遭遇和场景均使用稳定 ID。`meta.sequence` 为 1–7，显示日期为 11 月 5–11 日，互动额度依次为 `2/2/3/2/3/2/1`。

## 编写顺序

1. 在中文文件锁定当日目标、实体、路线、战斗和日期出口。
2. 运行 schema、引用、额度、路线和可达性校验。
3. 复制结构到英文文件，只翻译玩家可见文本。
4. 运行中英结构对齐。
5. 生成按语言和日期拆分的前端 JSON。

## 构建失败条件

- 字段未知、类型错误、稳定 ID 重复或引用不存在。
- 日期数量与 `duration_days` 不同，顺序不连续，或显示日期重复。
- 当日额度不是声明值，`main` 成本不是 1，或 `flavor` 携带效果。
- 中英文实体、条件、效果、顺序、额度、遭遇或出口不同。
- 11 月 7 日不能确定主路线，或并列时缺少免费确认流程。
- 任一日期没有下一日出口，或四个结局存在不可达路径。
- Happy 条件少于两条完成路线，或 True 不要求三路线和主体分离协议。
- 内容引用旧故事、旧结局或跨故事解锁条件。

## 本地化规则

Forus、NC 编号、HUMO、H-5 和用户名保持原样。英文采用自然本地化，但不得改变说话意图、线索强度、路线值、选项风险和结局条件。中文设计术语使用“中文名（`coding_name`）”；玩家可见正文不附带代码名。

## 审校重点

- NCO13、寰宇、Forus 项目组和 HUMO 职责不可互换。
- 聚合单元始终明确为代行者，不把发言相似直接等同于真人。
- 外部程序无名称、账号、头像、战斗单位或独立任务。
- True End 必须先移除真人账号权限，再讨论新主体资格。
- 青少年级内容不出现血腥、露骨伤害或现实仇恨煽动。
