# 测试与发布方案

## 内容与规则测试

- 校验故事包清单和 14 个日期 YAML 的 schema、中英结构、稳定 ID、引用和日期连续性。
- 验证每日额度 `2/2/3/2/3/2/1`、成功后扣除、失败回滚、提前结束、零互动、额度耗尽和未用额度不结转。
- 使用 10 日夹具验证运行时、路由和存档没有七日硬编码。
- 验证三路线进度、最高值主路线、并列免费确认和非主路线公共选项。
- 验证结局按 True、Happy、Good、Bad 优先，隐藏选项不泄露。
- 验证固定种子、基础三张手牌、正负手牌修正、出牌弃置、轮末全弃、牌堆不足再洗牌、双方防护和影响力伤害。
- 验证日期结束效果幂等，战斗重试不重复互动、效果或额度。

## 组件与集成

- 首次进入直接创建 H-5 周目，已有周目直接继续，不出现故事选择。
- 发帖、评论和回复生成正确父子关系，切换语言后语义与位置不变。
- 历史周目标记明确，不能改变当前路线或结局。
- 战斗胜负正确更新帖子、线索、牌组和日期出口。
- WebGL 适配包缺失、导入失败、初始化失败或上下文丢失时自动使用无操作实现。

## API 与安全

- 注册、登录、登出、会话撤销、重复用户名和错误凭据。
- Argon2id 哈希、Cookie 属性、会话轮换、Origin 拒绝、限流和请求体限制。
- `If-Match` 更新、过期修订 409、用户间隔离、游客上传和双向冲突覆盖。
- 日志不包含密码、会话令牌或完整存档。

## 端到端验收

1. 新游客从 11 月 5 日开始，提前结束一天并确认额度不结转。
2. 分别形成身份、治理和存续主路线，验证 11 月 8 日专属场景。
3. 达成 `everyone_online` Bad End。
4. 完成任一路线、胜利并封存，达成 `permanent_seal` Good End。
5. 完成两路线与审计包，达成隐藏 `full_disclosure` Happy End。
6. 完成三路线，在最终战执行主体分离协议，达成 `new_presence` True End。
7. 注册上传，在另一浏览器恢复并处理一次存档冲突。
8. 在未安装 WebGL 包的生产构建重复完成四个结局。

## 无障碍、性能与发布门槛

全流程必须支持键盘和屏幕阅读器；状态不只依赖颜色；正文达到 WCAG AA 对比度目标；常见手机宽度可完成阅读与战斗。论坛首屏不得等待视效，长列表分页或窗口化。

类型检查、内容校验、规则测试、API 测试、无障碍检查和四条结局端到端流程必须全部通过。WebGL 实现、帧率或视觉特效不属于首版发布门槛。
