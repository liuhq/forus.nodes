# 游戏设计总览

## 产品定位

Forus Nodes 是一款以论坛交互驱动叙事、以卡牌信息攻防处理冲突的短篇网页游戏。首发内容服务于求职作品集：玩家可在一次演示中看见完整的 React 界面工程、状态驱动叙事、WebGL 视效、响应式设计和安全云存档，而不需要先理解庞大世界观。

目标体验：

- 像进入一个已经存在很久的地方论坛，而不是点击传统游戏菜单。
- 玩家发出的每段文字都来自明确选择，并在帖子树和后续剧情中留下痕迹。
- 战斗是调查、论证和防护信息的抽象，不突然切换成无关的奇幻搏斗。
- 两个短故事分别提供友好的教学闭环与可重玩的三路线分支。
- WebGL 增强不遮蔽正文，不让低性能设备失去可玩性。

## 体验支柱

### 论坛即世界（`ForumAsWorld`）

首页、版块、帖子、个人页和通知构成完整游戏空间。故事入口是浔声小报的日期版块；章节推进体现为新帖、置顶、锁帖、编辑记录和站内通知的变化。

### 选择即发言（`ChoiceAsSpeech`）

玩家不能自由输入剧情文本。发帖、评论和回复均从有限选项中选择，发布后成为玩家账号的公开内容。选项描述立场和语气，但不展示隐藏数值。

### 冲突即信息攻防（`ConflictAsInformationCombat`）

证据提交、观点组织、来源保护和系统干扰被表现为卡牌战斗。战斗结果必须返回论坛，改变帖子状态、可见线索或路线。

### 历史可以重读（`ReplayableArchive`）

故事按整篇周目重启。玩家保留已读档案、图鉴和结局，但当前周目的证据与立场从头构建，避免永久解锁直接替玩家完成分支条件。

## 核心循环

```text
查看首页动态
  → 点击版块或通知
  → 阅读帖子与回复
  → 在互动时段内选择有限次发帖、评论或回复，或提前结束
  → 获得线索、卡牌或立场变化
  → 进行信息攻防
  → 论坛内容和权限更新
  → 进入下一帖子、章节或结局
```

单章目标时长 15–25 分钟。6 月故事完整周目约 30–50 分钟；11 月故事完整周目约 45–75 分钟。已读内容允许加速显示，但关键新选项和战斗不可自动跳过。

## 首发边界

首发包括两个故事、五章、五个结局、一套共享基础牌池和少量故事专属牌。不包含自由文本、多人、UGC、实时聊天、排行榜、付费系统、后台编辑器或第三个可玩节点城。

外部节点城只通过综合讨论、组织资料和失联事件建立世界规模，不生成支线任务。
